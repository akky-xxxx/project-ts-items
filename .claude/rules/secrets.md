# 機密情報の取り扱い

secrets・アクセストークン(npm の公開用トークン、GitHub のトークン等)・API キー・パスワードなど、漏洩すると第三者が外部リソースを操作できるようになる値を対象とする。以下ではこれらを「実値」と呼ぶ。

## 実値を書かない場所

- git 管理対象のファイル全般。実値を置いてよいのは gitignore 済みのローカルファイル(`.env` 系など)と、各サービスの secret ストア(GitHub / npm 等)だけ
- コミットメッセージ、PR のタイトル・本文
- `ai-communication/<作業ディレクトリ>/result_*.md` / `review_*.md`。git 管理外だが平文でローカルに残り、AI 間で受け渡される
- チャットへの応答、およびコマンドの実行結果として出力するログ

これらに書いてよいのは変数名と取得元(どのサービスの secret に登録されているか)だけで、値そのものは書かない。値を含む手順を説明する場合も `<YOUR_TOKEN>` のようなプレースホルダに置き換える。

## CI/CD での最小公開範囲

- secrets・環境変数は必要なジョブ/ステップにのみ渡す。ワークフローの top-level `env:` には置かない
- `permissions:` は既定を `contents: read` とし、必要なジョブでのみ広げる
- CI 専用の捨て値(漏れても実害の無い値)をワークフローに直書きする場合は、捨て値である旨をコメントで明記する
- CI 定義への secrets・環境変数の追加/変更と `permissions:` の変更は、`.claude/rules/ai-communication.md` の「設計フェーズに入る条件」にいう権限の変更にあたる

## `.env.example`(環境変数を参照するコードを追加した場合)

- アプリケーションやスクリプトがローカル実行時またはデプロイ先で参照する環境変数を追加・変更したら、その workspace の `.env.example` にも反映する(無ければ作成する)。CI のステップだけが使う変数(`GITHUB_TOKEN` のようにワークフロー実行時に注入されるもの)は対象外
- 書くのはプレースホルダか、ローカル開発専用の捨て値まで。実値は書かない
- 用途・必須か任意か・取得方法をコメントで添える

## 実値を書いてしまった場合

- push 前に気づいた場合はコミットを作り直す
- push 済み、または外部サービスへ送信済みの場合は、履歴の修正より先に値をローテーション(無効化・再発行)する。履歴を消しても、取得された可能性そのものは消えない
